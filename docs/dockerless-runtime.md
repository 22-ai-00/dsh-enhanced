# Linux 原生自迭代运行时

状态：实施中。目标是在无 Docker 的 Linux 安装中保留现有执行、学习、源码修复、独立验证、采用、发布与回退能力。本文定义交付边界；实现与实机证据不足时，不得把配置生成或单元测试通过当作完成。

## 不变的能力

| 能力 | 原生替代必须证明的结果 |
| --- | --- |
| 普通离线 shell | 有限 owner 授权、输入/输出和产物约束、原生 ToolRuntime 路由不变。 |
| 源码修复 | 精确 Git tree、离线冻结安装、完整仓库 `pnpm check`、目标包打包和输入/产物复核；不能替换为单插件编译。 |
| 工具创建、修订及回归 | 独立于候选的父进程观察、私有验收数据、原有验收与签名证书、有限采用及后续调用。 |
| 发布和回退 | 两次独立构建、确定性制品、SBOM/provenance、原有签名采用与物理回退链。 |
| 恢复 | 持久任务身份、冻结模型与预算、未知结果不重放、证明全部执行资源静止后才释放预留。 |
| 已有安装迁移 | 保留主人、会话、凭据、权限范围、授权期限、已用额度、历史证据与回退点；包括未授权创建的源码修复部署。 |
| 安装与更新 | 新装、源码准备、独立验证、更新及运行时不需要 Docker CLI、daemon、socket 或镜像。 |

macOS 已有 Seatbelt 路径继续保持其现有能力。它不具备 Linux 完整仓库源码替换合同，因此不能用其受限路径代替本次 Linux 改造。

## 执行边界

原生运行时使用按内容固定的工具链和依赖目录，替代 Docker 镜像。候选只读取获准的运行时目录与系统库，不读取 Host Home、凭据、状态库、验收答案、控制套接字或真实项目。运行环境显式构造，不继承 Host 环境。

Linux user/mount/PID/network namespaces 与 bubblewrap 负责文件、进程和网络视图。可信外层进程持有工作区；候选进入自己的 PID namespace，结束且完成资源核对之后才导出受限产物。工作区与临时目录使用内核 `size`、`nr_inodes` 上限的 tmpfs。拒绝链接、特殊文件和越界产物。

CPU、内存（含 swap）、PID 数使用实际内核 cgroup 限额，配置后读回验证。准备阶段只委派当前 UID 专属资源根；普通任务不执行通用 root 命令。候选的门控进程在获执行权前进入所有所需控制器。可信 keeper 不在候选组内，整组停止不能杀掉结果保管者。

v1 和 v2 分别验证。v1 使用 freezer 与 pidfd，在冻结、终止、重新观察及删除全部资源组后证明清理；v2 要求适当委派、domain 组、`cgroup.kill` 和递归 populated 证据。不存在控制器、迁入失败、资源身份变化或无法证明空组时报告未就绪或 unknown，禁止退回仅 rlimit、主 PID kill 或无界宿主执行。

普通 shell、行为验收和整仓构建使用不同的沙箱策略。整仓测试需要嵌套 bubblewrap；行为验收继续保留父/候选双进程的 syscall 和描述符保护。允许嵌套 namespace 的构建策略不得隐式用于行为验收。

## 持久合同与迁移

新增明确的 Linux 原生后端、资源身份和证据协议；不冒用 Docker 或 macOS 的边界标签。历史证据仍按原版本读取。旧 Docker 的未确认任务先按旧资源证明核对，不改写为原生任务、不重跑、不清零预算。

已有 owner 安装必须经过可恢复的签名配置迁移及服务切换，不能覆盖原有构建回执，也不能靠重新安装增加授权。新旧工具链与回退资源在切换验收前同时保留。目标和协调器继续复用原生 Automations 与 Cordis 生命周期，不新增模型循环。

## 验收顺序

1. 实机证明资源和 namespace 原语，包括正常执行、文件/网络边界、硬字节/inode/内存/CPU/PID 限额、超时和故障清理。
2. 接入普通执行与 Verifier 账本，验证重启恢复、撤销、unknown、幂等和历史迁移。
3. 接入整仓源码检查、创建/修订、独立行为验证、发布/采用/回退，保留原来的检查范围。
4. 完成无 Docker 安装和已有 owner 迁移，在没有可用 Docker CLI/socket 的环境验证真实完整路径。
5. 独立审查、根目录 `pnpm check`、公开包安装及实机部署验证通过后发布。普通任务的长期收益继续单独观察，不与本次去依赖验收混同。

## 当前实机发现

Linux x64 的 cgroup v1、namespace/seccomp 与固定工具链原语已经分别通过独立复核。namespace 覆盖非 root、无 capabilities、共享内存、终端、嵌套构建 namespace、Host 退出/停顿与控制 pipe 故障；工具链覆盖删除准备环境后从保留缓存在无网络环境中全新冻结安装。持久执行已接入 schema 8 账本和私有 Linux Verifier API：持久 intent 先于资源创建，keeper 与候选分别准入，收据与真实资源消失共同决定释放容量；临时故障可在同一 Host 内重试清理，未知任务不重派。历史后端身份与已用预算保持不变。显式配置的普通工具与 operator 恢复/探针已通过集成与范围内独立复核；安装器、完整源码及自迭代采用链尚未接通，不能据此宣称完整能力等价。

本机为 cgroup v1；`systemd-run --user` 对 MemoryMax/TasksMax/CPUQuota 返回成功，但进程未进入这些控制器的独立任务组，因此这不能作为硬配额证明。原生 system 级任务确有独立控制器组。已验证用户 namespace 与 bubblewrap 可执行；bubblewrap 的 `--size` 单独只限制 tmpfs 字节数，不能代替明确的 inode 限额。实现必须覆盖这些差异。
