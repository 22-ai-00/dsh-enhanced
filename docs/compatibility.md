# 兼容性基线

本页记录当前已验证的 DSH / Cordis / Node 运行时契约、CLI 与第三方适配器边界，以及跨包存储迁移规则。过往版本的逐期变更历史见 Git 提交记录。

## 0.2.2-rc.5 Host 基线与工具链

当前桌面 Host 与仓库验证基线锁定为 **DSH `0.2.2-rc.5`**：

- DeepSeek Harness 运行时与 npm 测试依赖：`0.2.2-rc.5`（workspace catalog 与源码安装同步固定）。
- **包与 peer 范围**：所有插件与共享包的 `@deepseek-ai/*` peer 范围收紧为 `>=0.2.2-rc.5 <0.3.0`，`@deepseek-ai/cordis` 为 `^4.1.0`（锁定 Loader / Include / Group `1.1.0`，参见 [Cordis runtime contracts](cordis-runtime-contracts.md)）。Host 使用 `semver.satisfies(..., { includePrerelease: true })` 检查范围；根 `tests/dsh-compatibility.spec.ts` 拒绝低于 `0.2.2-rc.5` 的基线或未验证的 `0.3.x`。已发布包基线以[发布账本](../release-manifest.json)为准。
- **Node.js 与 pnpm**：工作区 `.node-version` 锁定 Node **`24.9.0`**，根包、全部 40 个发布包（36 个插件 + 4 个共享包）及插件模板的 `package.json` 均声明 `engines.node: ">=24.9.0"`；当前安装脚本预检（`scripts/install/common.sh`）仍兼容 Node `22.19+ || >=24`，Linux bwrap 行为隔离与 CI 验证节点（`.github/workflows/ci.yml`）使用 `/usr/bin/node` **`v22.23.2`**，包管理器锁定 **`pnpm@11.7.0`**。本页为全仓运行时与版本基线的单一权威来源，各包 README 统一指向本页。
- **依赖边界与无自引用约束**：插件不得把 `@deepseek-ai/dsh-*` 运行时包写成普通 `dependencies`（否则 Loader 会优先解析 profile 内旧副本并禁用 `working-directory`、`session-projection` 等根服务）；非必需的兄弟插件集成（例如 `assistant-dreaming` 读取可选业务插件服务）须声明为可选 `peerDependencies`。
- **循环构建引导（`build:bootstrap`）**：针对存在循环 `devDependencies` 的包组，根 `pnpm run build` 先按序执行 `build:bootstrap`（共享包 `packages/*` → `assistant-policy` → Evaluation `build:core` → Delivery → Isolation → Evaluation → Verifier → Automations → Preference Learning / Health / Evolution / Growth Experiments / Heartbeat / Recovery / Goals / Skills / Control Plane / Personal Memory / Memory Learning / Keychain / Actions / Event Triggers / `assistant-dreaming`），再以 `--workspace-concurrency=1` 递归构建全部工作区及前端产物（如 `owner-console/lib/client.js`）。
- **DSH `0.2.2-rc.5` 运行时契约**：
  - 使用显式 `ToolExecutor`（`@deepseek-ai/dsh-tool-executor-native` / `@deepseek-ai/dsh-tool-executor-ptc`）、批量 `tools.execute(ToolBatchInput)`、Session format `4`、生产者专属 `MessageSource`、顶层工具结果消息与 `agent-preset-registry`。
  - Agent setup 第二参数为确切未发布 Agent 实例（不再使用 `ctx.agent`）；子任务使用 `SubagentRuntime.startActivation()`；系统提示组装使用 `system-prompt/assemble` 并支持 `runtime-context` 用户消息与 suppression；自定义 setup CLI 通过所选 Host 原生 `createRuntimeResolution` 与 `PluginPackages` 解析，不依赖已移除的 fallback API。
  - **助手审批与 Harness 原生 Auto 分离**：Policy 不注册保留档位 `auto`，也不凭原生 Auto 选择启动项目 reviewer；助手 `/permission auto` 基于 `workspace-write + ask` 与 required reviewer 事件；安装器与 `dsh-permission-setup` 只接受 `workspace-write` / `danger-full-access` 静态默认。

## 插件配置、UI 与多编程 Agent 兼容

- **配置与预设（`dsh-plugin-setup` / `assistant-policy`）**：覆盖 `owner-console`、`assistant-proactive`、`assistant-dreaming`、`assistant-growth-driver`、`assistant-memory-learning`、`assistant-work-items`、`assistant-delivery`、`assistant-evolution`、`assistant-verifier`、`preference-learning`、`assistant-evaluation`、`assistant-goals`、`event-triggers`、`assistant-association`、`personal-memory` 与 `personal-assistant` 共 16 个已登记可选键（`knownOptionalKeys`）。R3 默认开启全套自迭代与联想开关，`assistant-association`（含 S1–S4 默认开启）现已直接纳入 `web` / `lark` / `supervised` 常规安装队列；`preset recommended` 按前置启用安全观测开关，`preset dogfood` 仍保留用于记忆/偏好自用档案；`assistant-dreaming` 在缺少 `scope`、`$DSH_HOME` `databasePath`、`provider`/`model` 与 `budgetId`/`budgetAmount` 时保持 fail-closed 休眠（6 项前提齐备后条件性默认激活）。`assistant-policy` 与 `dsh-plugin-setup` 另为 `dsh-ray-assistant-proactive` 登记 `intakeEvaluation.preset`（`conservative` / `balanced`，对应 `dsh-intake-github-mention-or-review`、`dsh-intake-calendar-imminent`、`dsh-intake-webhook-priority`、`dsh-intake-file-watch-change`），`assistant-proactive` 支持按 preset 展开规则配置。
- **Owner Console（`owner-console`）**：发布 `./client`（`lib/client.js`），向 DSH 原生左栏注册 `sidebar.panellist`、`main`、`settings.section`、`settings.section.icon`、`settings.general.item`、`settings.models.footer`、`settings.models.provider-card` 及 6 个 `plugins.bundle.config` 槽位；所有配置与包管理写入经 Host `settings` / `pluginManager` 或受控 Typert remote，浏览器侧不持密钥、不直连模型。
- **ACP 双编程 Agent（`traex-acp-provider` / `dsh-model-setup`）**：基于 ACP SDK `0.25.1`（protocol v1）在同一包行同时支持 `traex-agent`（`enabled` / `command`，`traex --sandbox read-only --ask-for-approval never acp serve`，`traex login status`）与 Antigravity CLI `agy-agent`（`agyEnabled` / `agyCommand`，`agy acp --sandbox --include-default-customizations=false --disable-telemetry --stdio`，无交互 `agy models` 探活、交互 `agy` 或 `agy acp --login` 登录），支持 `.volatile()` 配置热重载；注意 `agy acp` 缺少 `--ask-for-approval never`，请勿在不可信仓库配置本地 auto-approve。
- **其他外部 CLI 与渠道基线**：
  - `coding-subscription-provider`：Codex CLI `0.147.0`–`0.150.1` 或实验性 direct-responses、Claude Code `2.1.218`、Grok Build `1.0.5`、Cursor CLI（实验性未实机验收）。
  - 飞书渠道：`@larksuiteoapi/node-sdk@1.76.0`（含长连接卡片回调桥与 table 行高适配）；`DeliveryAdapter.capabilities.textAttachments: true` 支持 WP19 超限纯文本/Markdown UTF-8 文件上传与发送（默认开启 `attentionAttachOverCap: true`）。
  - 安装期 `pnpm` 11 ANSI 构建审批兜底：写入 profile `pnpm-workspace.yaml` 的受限决策表（`koffi: true`、`protobufjs: false`），并支持半装 bundle 自动恢复。
- **Stage 3 事件源、附件投递与评估同步契约（R3 默认开启，可选 peer 注入）**：
  - `event-triggers` 8 类 sensor（`github-repository`、支持滚动时间窗的 `lark-calendar`、`file`、`http-json`、内置 `webhookListen` 监听的 `webhook`、`task-system`、非飞书 `calendar` 与 `email`）默认开启 `pollerEnabled: true` 并按触发器 opt-in `intake` 适配器，通过 `registerIntakeObserver` 与可选 peer `assistantWorkItems.recordIntake` 严格投影至闭集 10 键 `WorkItemIntakeInput`；`assistant-proactive` 与 `event-triggers` 在 `goal/changed` 终态、`closeWait` 或 `retireGoalSources` / `unsubscribeGoalSources` 时联动自动退订 `observerLifetime: 'goal'` 来源（无轮询定时器）。
  - `assistant-delivery` Web `noticeAdapter`（`capabilities.textAttachments: true`，经 `NativeWebOwnerAccess.notifications` → `assistant-web-owner` `DeliveryNotice.attachment` / `DeliveryNoticesService`）与 `lark-channel`（`textAttachments: true`）端到端承载 `attentionAttachOverCap` 超限文本附件（R3 默认同时开启 `attentionAttachOverCap: true` 与 `attentionEnforce: true`）。
  - `assistant-work-items` 只读 `listIntakeEvaluationFeed`（`work-items/intake-evaluation-feed/v1`，无正文/原始 brief）供 `assistant-evaluation`（默认开启 `intakeEvaluationAgreementEnabled: true`）经 `IntakeEvaluationAgreementLedger` 增量同步（页上限 `intakeEvaluationFeedBatchSize` 默认 `100`、最大 `500`）并纳入 `lane: 'intake'` 密封留出重放（`attentionHoldoutMember` / `replayAttentionLoosening`）。

## 跨包存储、隔离与升级边界

- **只增 / 不可降级 SQLite 账本**：WorkItems schema 10–14（intake / evaluation / admission / provenance index，schema **14** 新增 WP21 `work_item_intake_staging` 与 `work_item_intake_eval_queue`）、Delivery schema 24–31（自然反馈 / 同码维护重启见 [Delivery](../plugins/assistant-delivery/README.md#受控维护重启) / 独占续办与报告反馈 / 注意力审计）、Evaluation schema 12–19（canonical writer fence / 通知结果与 WP22 主人提问 / schema **19** WP20 `would-accept` 吻合度账本：`evaluation_intake_evaluation_sync_cursor`、`evaluation_intake_evaluation_heads`、`evaluation_intake_evaluation_revisions` 与单调/不可改触发器及严格 `schema-drift` 校验）、EventTriggers schema 5–6（outbox 序号与 `goal_source_claims` 目标来源认领/退役，schema **6** 新增 `trigger_cursor`）、Memory schema 5–7（知识导出 v2 与有限经验采用；`assistant-memory-learning` 任务账本 schema 2）、Association schema **4**（`assistant-association` S1–S4 关联图、留出、Hebbian/WP22 参数版本链、做梦/聚类/评估池及 S4 Web 学习账本）、Isolation schema 9–10（`defaultSchemaVersion = 9`、`maxSchemaVersion = 10` / `ensureSchema10`，含 `linux-native` 资源预留；审计归档线协议为 `dsh-isolation-audit-archive/v1`（manifest `version` 1 / `.archive-control.sqlite` `user_version` 1），Linux 隔离执行与仓库契约协议为 schema 2–3）、Control Plane schema 15–41。升级前须停止旧 writer；降级打开新版数据库一律 fail-closed。
- **跨平台隔离（`assistant-isolation`）**：`backend` 支持 `'auto' | 'linux-native' | 'macos-seatbelt' | 'windows-job'`（默认 `'auto'` 自动匹配当前平台，Linux 唯一原生后端为 `linux-native`：bubblewrap、user/mount/PID/network namespace 与有界 tmpfs）。`scripts/isolation/prepare-linux-cgroups.mjs --auto`、`discoverLinuxCgroupRoots`、`dsh-ray doctor`、`assistant-isolation` 运行时进程迁入及 `assistant-verifier` / `plugin-control-plane` / `assistant-web-owner` 配置与 authority 编译器均支持已委派 cgroup v1 四控制器或统一 cgroup v2 子树（`/sys/fs/cgroup/dsh-native/uid-<uid>` 及 `systemd --user` `.../user@<uid>.service/dsh-native/uid-<uid>`，含共同祖先 `cgroup.procs` 写权限与 `cgroup.freeze` + `cgroup.kill` 终止）。Docker 构建与执行后端已移除，历史 Docker ledger 与 `isolated-runner` 配置仅保留只读解码供迁移校对；macOS/Windows 内核级路径在本地通过跨平台 DI 与单测覆盖并由 CI `macos-verify` / `windows-acp-smoke` 门禁验证。
- **Host 升级与 `docker→native` 迁移**：
  - 通用 `dsh-ray install` 解析官方 `latest` 并锁定到已验证基线，将绑定入口写入 `$DSH_HOME/.dsh-ray-host.json`。
  - `dsh-ray update --all --yes` 对冻结 Linux owner Home 支持从历史 Docker 后端或旧 Host（`0.2.0-rc.2` / `0.2.1-rc.2` / `0.2.2-rc.1` / `0.2.2-rc.3` / `0.2.2-rc.5`，目标固定 `0.2.2-rc.5`）迁移与升级；普通本地自助升级 `dsh-ray upgrade` 与 `upgradeAssistantAndRecover`（CLI 与 Web/飞书 NL 控制）已支持 Host `0.1→0.2`、已有 owner 原地升级（`--upgrade-owner`）及默认开启非空创建/审查历史迁移（`allowNonEmptyHistoryMigration: true`，带备份、`doctor` 体检、受管服务重启与失败回滚保护）。详情见[维护说明](../scripts/install/maintenance.md#现有-linux-冻结-owner-程序升级)、[CLI 升级与重装](../packages/dsh-ray/README.md#升级与重装)、[联合迁移](../scripts/install/README.md#旧-home-的联合-host--源码迁移)与[首次 owner 修复](../scripts/install/README.md#已-applied未首次采用的-owner-修复)。
  - Linux service-aware `supervised` 升级要求 systemd user manager、`flock`、Perl、`/usr/bin/python3`、bubblewrap 与同文件系统 `DSH_HOME`（`renameat2`），预览过程只在隔离副本内临时屏蔽 `larkChannel`。

## 本地源码维护历史（Control Plane schema 28）

schema 28 在停服副本事务中为冻结源码保留不可变 `initialCommit`、签名维护链及部署 watch 锚点（readonly store 使用 SQLite immutable 模式并先核验已 checkpoint、无未结 WAL）：

- 仅当原安装具备空 owner 权限、有效私有 Host 收据与对应协调器占位时，checkout 内 pre-owner 维护事务才允许更新 runtime/release/cohort（含 `--add-memory-learning` 扩展受审 AST 核对）；已建立 owner/coordinator 的通用源码升级仍保留隔离限制。
- 动态插件候选创建/修订（支持 `'tool' | 'service' | 'channel' | 'ui'`）与采用沿 Control Plane schema 27–41 与 Verifier 独立回归/保持用例运行，并保留物理回退与签名证书账本；`assistant-delivery` 默认注册 `inProcessReload`（`enabled: true`），`PluginControlPlaneService` 已将其自动接入 `AdoptionCoordinatorRuntime` 执行路径（`IN_PROCESS_RELOAD_DENYLIST` 仅包含 `@dsh-ray/plugin-control-plane` 与 `@dsh-ray/assistant-delivery`，支持 `config-only` 与非 denylist 插件的不可变 `<version>-<artifactDigest>` `artifact-replace` 及失败自动回滚）。具体门禁见 [新工具插件的有限动态采用](../plugins/plugin-control-plane/README.md#新工具插件的有限动态采用)、[同进程重载](../plugins/plugin-control-plane/README.md#同进程重载configpatch-与不可变-artifact-替换)、[已发布 owner 修复的有限采用](../plugins/plugin-control-plane/README.md#已发布-owner-修复的有限采用) 与 [自动创建新插件候选](../plugins/plugin-control-plane/README.md#自动创建新插件候选)，最新交付边界以 [RSI 状态](rsi-status.md) 为准。
