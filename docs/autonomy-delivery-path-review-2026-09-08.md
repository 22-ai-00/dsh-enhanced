## 本次复审的执行决定（基线 `e4044f5`）

主要瓶颈是已实现能力迟迟未冻结、生产组合的首次验证偏晚，以及外部前置条件没有与下一场景一起固定。继续拆出新组件不会缩短当前交付路径。本批冻结仓库新鲜验收和有限技能回滚两条已有实现，修复实际阻塞、独立复核、一次完整工程检查后提交；不把事件观察器、自动候选和推广继续追加进来。

下一批唯一主场景：明确仓库/分支/来源授权 → 步骤验收后 PR → CI pending 时等待 → Host 重启 → 一种仓库状态事件 → 原 Goal 恢复并重读准确 head → CI/评审达成 → 原会话反馈。优先把旧测试中的来源观察执行器换成正式 Host 配置，复用 EventTriggers/Automations，不扩多平台事件系统。事件本身不授予成功，实际远端回读仍负责验收；真实 GitHub 访问前置未满足时明确标记该场景未完成。

预算跟着这个场景核算：初始 branch read、commit、PR 共 3 次；每次新鲜验收另用 4 次动作。`maxActions: 7` 只足以一次 ready 回读，不能证明 pending 后还能继续。下一场景须显式限定允许回读次数并覆盖相应额度、目标轮次、等待期限与验证窗口，不能通过自动加额或固定提高一个最低数字保证无限跟进。

唯一独立辅助线继续 Skills 候选生成 → 独立比较资格 → 受限启用。当前比较明确记录 `heldoutIndependence: unproven`，有限回滚也不证明改进收益；封闭留出与晋升条件仍是硬前置。不得为主线的外部等待扩大辅助线到通用监控或另一套成长运行时。
